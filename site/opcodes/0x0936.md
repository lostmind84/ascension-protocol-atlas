# `0x0936` SMSG_PATCH_ACHIEVEMENT

**server to client** · status `unknown` · evidence `L3` · layout `widths` · client code `handler`

Fiche: [`protocol/opcodes/0x0936-smsg-patch-achievement.yaml`](../../protocol/opcodes/0x0936-smsg-patch-achievement.yaml)

One row of the stock Achievement.dbc (AzerothCore already loads this table; ADR 0005), sent as an opaque 56-byte blob (RVA 0x00229fb0, no per-field split available) followed by 3 lpstrings. AchievementEntry has 8 active numeric members (ID, requiredFaction, mapID, categoryId, points, flags, count, refAchievement) and 3 locale-string blocks in the file (name, kept; description and titleReward, both fully commented out) -- a count that happens to match the 3 trailing lpstrings, but neither count reconciles with the 56-byte/ 14-dword blob (56/4=14, not 8 and not the 11 non-string columns the file actually has), and the blob is a single un-individuated read with no internal field boundaries to anchor a positional mapping. DBCStructure.h (AchievementEntry) and DBCfmt.h (Achievementfmt) were checked; no naming source was found that is safe to assert here (docs/EVIDENCE.md: "an honest 'no naming source found' ... is worth more than a plausible guess"). Nothing in the layout is renamed. Read against the real decompiled handler (build/ghidra/handlers-c/0x0936.c): the 14 dwords are read via fixed byte offsets from one base (not the sequential position-tracked reads seen elsewhere in this bucket), landing on dword indices 0,1,2,3,6,7,8,9, 10,12,13 -- 11 named values with indices 4, 5 and 11 read (the block's width still accounts for them) but never stored to a named variable. That index gap does not correspond to AchievementEntry's known column gaps at all (name[16] starts at column 4 in the file), which confirms this 56-byte block is some other, custom packing rather than a slice of the file's raw column order -- consistent with the pattern already seen on 0x0941, where the wire's numeric fields are gathered in a different order than the file's columns. Not enough to name any individual field here.
