# `0x09B2` SMSG_SPELL_ACTIVATION_HIDE

**server to client** · status `hypothetical` · evidence `L3` · layout `named` · client code `handler`

Fiche: [`protocol/opcodes/0x09b2-smsg-spell-activation-hide.yaml`](../../protocol/opcodes/0x09b2-smsg-spell-activation-hide.yaml)

The CoA server calls it `SMSG_COA_SPELL_ACTIVATION_HIDE`.

Remove the spell-activation overlay from a spell's button. The server writes u32 spellId and a u32 zero; the client's handler read sequence goes on for six more fields (u32, u32, f32, u32, u32, u32) it will not find in an 8-byte packet -- the CDataStore Gets are bounds-checked, so those reads yield nothing rather than fail. Whether the client behaves as intended with the short packet is a lab question (docs/ROADMAP.md, P4).
