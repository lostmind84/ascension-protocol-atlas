# `0x0800` CMSG_MULTIPLE_MOVES_BETTER

**client to server** · status `unknown` · evidence `L3` · layout `unknown` · client code `none`

Fiche: [`protocol/opcodes/0x0800-cmsg-multiple-moves-better.yaml`](../../protocol/opcodes/0x0800-cmsg-multiple-moves-better.yaml)

Named CMSG_MULTIPLE_MOVES_BETTER by the client's own opcode table -- not the same opcode as AzerothCore's own SMSG_MULTIPLE_MOVES (0x51E, "uncompressed version of SMSG_COMPRESSED_MOVES", `src/server/game/Server/Protocol/Opcodes.h:1340`), and not a duplicate of it: different number, different direction, and this one is client-to-server. `client/client-senders.md` states plainly that this opcode "is a name with no trace either": not a 32- or 16-bit immediate in `.text`, not a value in `.rdata`/`.data`, not an arithmetic constant before a `Put(u32)` opcode write, and not a number in the shipped Lua. This build has no sender for it; layout is not established because there is nothing to read, not because nobody has looked. The three files this fiche used to cite under `used_by_server` were checked by hand and are false positives of a bare-literal scan: `0x0800` in each is an unrelated bitmask (`GameModeDef`'s `BuildDraft` bit and `REGEN_CAST_RANGE`), never an opcode. See the retraction in provenance.
