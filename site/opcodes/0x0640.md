Named SMSG_RECOLOR_COLLECTION_LIST by the client's own opcode table, first of "the recolor family" the capture reference names (0x0640-0x0642: list, added, removed -- see the other two fiches). The client registers no handler for 0x0640. The registration scan (`handlers.yaml`) is exhaustive over every static `push handler; push opcode; call <registrar>` site across all three registrars Extensions.dll uses (532 total registrations, including the far-higher 0x09bf in an unrelated family -- see that fiche), so the usual "Extensions.dll-only" caveat for a *standard* opcode (client/symbols/.../handlers.md) does not apply here: 0x0640 is outside AzerothCore's baseline entirely (protocol/known-baseline.yaml). Unlike the rest of this pass's opcodes there is not even a superseding name to point at: nothing in the client's Lua binding table or the UI corpus mentions "recolor", "dye", "tint" or a colour-collection concept under any name -- the live appearance-collection events are APPEARANCE_ADDED/APPEARANCE_REMOVED (0x069b/0x069c), which are about item appearances, not colours. Whatever "recolor collection" meant, this build carries no trace of the concept at all, not just an old opcode number for it.
