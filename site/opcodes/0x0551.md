Named CMSG_TRANSMOG_OUTFIT_CREATE_ID by the client's own opcode table: the last of five consecutive TRANSMOG_OUTFIT_* CMSGs (0x054d-0x0551 -- MOD_APPEARANCES, MOD_NAME, APPLY_ID, REMOVE_ID, CREATE_ID), an old per-outfit CRUD surface; this one creates a new saved outfit under a server-assigned id. Nothing in this build constructs a packet with this opcode: no `push 0x551` / `mov r32, 0x551` occurs anywhere in Extensions.dll's `.text`, byte-exhaustively. The live feature creates and saves an outfit in one call, CMSG_SAVE_APPEARANCE_OUTFIT (0x069e, registered and sent in this build -- not ours; the capture reference describes it as `{cstring name; u32 n; u32 appearanceId[n]}`), with no separate create-by-id step. This is not "we have not found the sender yet"; it is "this build has no code that could send it."
