# `0x0581` SMSG_GROUP_FINDER_UPDATE_LISTING_RESPONSE

**server to client** · status `hypothetical` · evidence `L3` · layout `named` · client code `handler`

Fiche: [`protocol/opcodes/0x0581-smsg-group-finder-update-listing-response.yaml`](../../protocol/opcodes/0x0581-smsg-group-finder-update-listing-response.yaml)

Answer to a group-finder update-listing request: a u32 result code, 0 meaning ok, then -- on success only -- one length-prefixed string the handler reads with FUN_100d3680 and hands to GROUP_FINDER_ACTIVITY_UPDATED(%s); on failure the code indexes the UPDATE_LISTING_* table (client_enums) and GROUP_FINDER_ACTIVITY_UPDATE_FAILED fires with that string. The string after a success is what the handler passes to the event: the listing's identity, not read further.

| field | type | evidence | notes |
| --- | --- | --- | --- |
| `result` | `u32` | L3 | 0 = ok; otherwise an index into the client_enums table |
| `listing` | `lpstring` | L3 | present only when result is 0 |
