# `0x092C` SMSG_PATCH_SPELL_VISUAL

**server to client** · status `hypothetical` · evidence `L1` · layout `named` · client code `handler`

Fiche: [`protocol/opcodes/0x092c-smsg-patch-spell-visual.yaml`](../../protocol/opcodes/0x092c-smsg-patch-spell-visual.yaml)

One row of the stock SpellVisual.dbc (AzerothCore already loads this table; ADR 0005), sent as the single 128-byte blob the handler at RVA 0x002331f0 reads (L3, no per-field split available). Nothing was elided (32 cols x 4 bytes = 128 bytes matches the client header exactly), so the blob is decomposed here one dword per column in file order. Only 3 of 32 are named: HasMissile and MissileModel are SpellVisualEntry's only active members; Id is FT_SORT ('d') and commented out of the struct but DBCStructure.h still labels it. The other 29 are core 'x' columns with no name anywhere in AzerothCore (L1 for the 3 names and for the column boundaries themselves, since only the total width was independently decompiled).
