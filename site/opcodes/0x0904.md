# `0x0904` SMSG_PACKET_BROADCAST

**server to client** · status `hypothetical` · evidence `L3` · layout `named` · client code `handler`

Fiche: [`protocol/opcodes/0x0904-smsg-packet-broadcast.yaml`](../../protocol/opcodes/0x0904-smsg-packet-broadcast.yaml)

A packet envelope: two guids, a range and a complete inner packet (opcode and body) that the client dispatches to itself as if it had received it. The server uses it to make a client near another one replay an arbitrary opcode locally; the client drops it when either guid is its own or the two objects are farther apart than the range.

## Layout

| field | type | evidence | notes |
| --- | --- | --- | --- |
| `senderGuid` | `u64` | L3 | the packet is dropped when this is the active player's guid |
| `targetGuid` | `u64` | L3 | dropped when this is the active player's guid; otherwise both are resolved through the object manager (exe 0x004d4db0, mask 0xffff) |
| `range` | `f32` | L3 | squared against the distance between the two objects: the inner packet is dispatched only inside it |
| `innerOpcode` | `u16` | L3 | written as the first two bytes of the store handed to the dispatcher |
| `innerSize` | `u16` | L3 | byte count of the payload that follows |
| `innerPayload` | `bytes_variable` | L3 | innerSize bytes, copied after the opcode into a fresh CDataStore of innerSize + 2, which is handed to the exe's ClientServices::ProcessMessage (0x00631fe0) and so runs through the normal dispatch, DLL handlers included |
