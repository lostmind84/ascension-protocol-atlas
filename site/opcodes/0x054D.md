Fiche: [`protocol/opcodes/0x054d-cmsg-transmog-outfit-mod-appearances.yaml`](../../protocol/opcodes/0x054d-cmsg-transmog-outfit-mod-appearances.yaml)

Named CMSG_TRANSMOG_OUTFIT_MOD_APPEARANCES by the client's own opcode table: one of five consecutive TRANSMOG_OUTFIT_* CMSGs (0x054d-0x0551 -- MOD_APPEARANCES, MOD_NAME, APPLY_ID, REMOVE_ID, CREATE_ID), an old per-outfit CRUD surface. Nothing in this build constructs a packet with this opcode: no `push 0x54d` / `mov r32, 0x54d` occurs anywhere in Extensions.dll's `.text`, byte-exhaustively. The live feature collapses the same five actions into two verbs, CMSG_SAVE_APPEARANCE_OUTFIT (0x069e, registered and sent in this build -- not ours; the capture reference describes it as `{cstring name; u32 n; u32 appearanceId[n]}`, one call that both creates and edits an outfit by name) and CMSG_DELETE_APPEARANCE_OUTFIT (0x06a0, also live). This is not "we have not found the sender yet"; it is "this build has no code that could send it."
