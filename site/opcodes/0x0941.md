One row of the stock Faction.dbc (AzerothCore already loads this table; ADR 0005). Reading the actual decompiled handler (build/ghidra/handlers-c/0x0941.c, RVA 0x0022c140) by hand resolves the earlier concern that this record looked severely under-read: it is sent in full. 19 dwords (ID, reputationListID, BaseRepRaceMask[4], BaseRepClassMask[4], BaseRepValue[4], ReputationFlags[4], team) match FactionEntry's first 19 active members in declaration order exactly, via 4 short copy loops the coarse extractors had not unrolled; then 4 more raw dwords (spilloverRateIn, spilloverRateOut, spilloverMaxRankIn, and the commented-out parentFactionCap) match columns 19-22 exactly; then 2 lpstrings match the file's 2 real locale-string blocks (name, kept; description, commented out) in file order. 19+4+2 = 25 reads covering all 57 columns (23 numeric + 2x17 string-slot columns collapsed to 1 string each), with nothing left over. 22 of 25 fields are named from DBCStructure.h (L1); parentFactionCap and description are core 'x' columns, identified with confidence but kept unnamed per that convention.
