# `0x05AC` SMSG_CHALLENGE_CREATOR_QUERY_CHALLENGES_RESULT

**server to client** · status `hypothetical` · evidence `L3` · layout `named` · client code `handler`

Fiche: [`protocol/opcodes/0x05ac-smsg-challenge-creator-query-challenges-result.yaml`](../../protocol/opcodes/0x05ac-smsg-challenge-creator-query-challenges-result.yaml)

The CoA server calls it `SMSG_COA_TRIAL_DATA`.

The custom-trial list for the challenge creator. A clear flag, a fire flag, a count, then one trial record each: id, an owned byte, four more strings this fiche does not identify, a list of (challengeId, level, description) entries, the viewer's two vote bytes and two lists of (guid, 0) vote records. TRIAL_QUERY_RESULT fires at the end when the second byte is set. The DISAGREEMENT recorded against this opcode is RESOLVED: the fork's SendTrialData writes exactly this shape, field for field. The 2026-09-19 check saw fewer server fields because server_layout.py skips an AppendConfigString whose argument is a call expression (the three middle strings) and does not follow AppendVoteList (the two vote lists), and because it concatenated both branches of the empty-result if.
