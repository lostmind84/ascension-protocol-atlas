Named CMSG_TRANSMOG_OUTFIT_MOD_NAME by the client's own opcode table: one of five consecutive TRANSMOG_OUTFIT_* CMSGs (0x054d-0x0551 -- MOD_APPEARANCES, MOD_NAME, APPLY_ID, REMOVE_ID, CREATE_ID), an old per-outfit CRUD surface; this one the rename action. Nothing in this build constructs a packet with this opcode: no `push 0x54e` / `mov r32, 0x54e` occurs anywhere in Extensions.dll's `.text`, byte-exhaustively. The live feature has no separate rename call at all -- CMSG_SAVE_APPEARANCE_OUTFIT (0x069e, registered and sent in this build -- not ours) takes the outfit's name as part of the same save call the capture reference describes (`{cstring name; u32 n; u32 appearanceId[n]}`), so a rename is just a save under a different string. This is not "we have not found the sender yet"; it is "this build has no code that could send it."
