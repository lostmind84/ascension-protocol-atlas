# `0x0023` SMSG_GODMODE

**server to client** · status `hypothetical` · evidence `L1` · layout `named` · client code `none`

Fiche: [`protocol/opcodes/0x0023-smsg-godmode.yaml`](../../protocol/opcodes/0x0023-smsg-godmode.yaml)

AzerothCore defines 0x0023 as SMSG_GODMODE and declares it STATUS_NEVER -- the core never sends it -- and Ascension's client keeps the same inherited name in its opcode table. A third-party capture of a live Ascension session reports the realm using the number for something else entirely: three length-prefixed string lists, 79 entries in all, that read as an anti-cheat detector signature set (process and module names, short file tokens, window-title fragments). The name in the table therefore says nothing about the content. Our own contribution is negative and re-derivable: none of the reported signature strings exists in the stock client binaries, so a list like this cannot be compiled in and has to arrive at runtime, which is consistent with a packet carrying it. That does not prove the packet is this one. The client's own anti-cheat reports go back the other way on CMSG_ANTICHEAT_ALERT (0x051f) and CMSG_ANTICHEAT_VERSION (0x0520).
