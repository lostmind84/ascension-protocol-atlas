# `0x05A3` SMSG_CHALLENGE_FAILURE

**server to client** · status `hypothetical` · evidence `L3` · layout `named` · client code `handler`

Fiche: [`protocol/opcodes/0x05a3-smsg-challenge-failure.yaml`](../../protocol/opcodes/0x05a3-smsg-challenge-failure.yaml)

The CoA server calls it `SMSG_COA_CHALLENGE_FAILURE_ADDED`.

One challenge-failure record, appended to the failure list and followed by CHALLENGE_FAILURE_ADDED. Twenty-seven fields, read by the parser FUN_1013f230: a length-prefixed string, seventeen numeric fields (two of them read as 64-bit lo/hi pairs, three of them single bytes), six more length-prefixed strings and four trailing u32. The record is packed from +0x34 on and ends at +0xef -- exactly the stride the handler advances by, so the map is complete. Only challengeId and level are named, from the event the handler fires; the client's UI documents all twenty-four keys of the record it receives (WorldMapPOIMixin.lua:147-171, L2) but nothing here binds a key to a slot.
