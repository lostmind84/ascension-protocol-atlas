# `0x0900` SMSG_UNNAMED_0900

**server to client** · status `hypothetical` · evidence `L1` · layout `named` · client code `none`

Fiche: [`protocol/opcodes/0x0900-smsg-unnamed.yaml`](../../protocol/opcodes/0x0900-smsg-unnamed.yaml)

Unnamed in the client's own opcode table and with no handler registration in Extensions.dll: on this build the client drops whatever arrives here (client/symbols/ascension-extensions-2026-08-13/handlers.md says so in as many words). A third-party capture of a live Ascension session nevertheless reports the real realm sending a 94-byte frame on this number during the enter-world burst: a count of nine, then nine ten-byte records whose first word descends from 762 to 94. The id space is unidentified by them and by us. azerothcore-wotlk-coa#4128 sends its own SMSG_COA_CONFIG on the same number, which is a different payload claim on the same empty slot. Direction is inferred, not read: both sources have the server sending it, and our own sender scan finds no send site for it in the client.
